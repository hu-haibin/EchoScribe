# 语音转文字 UX 交互流程审计

本文档整理当前项目的真实交互、用户不方便的点，以及推荐的音频、视频、多文件/批量 UX 规划。

依据：

- 代码审计：`src/App.tsx`、`src/components/HomePage.tsx`、`src/components/LyricsView.tsx`、`src/components/PlayerBar.tsx`、`src/components/ExportMenu.tsx`、相关 stores。
- 真机 smoke：本地启动 `http://127.0.0.1:5173/`，实际测试多音频上传、返回首页、切换文件、编辑字幕、导出 TXT、上传视频。
- Claude 只读审计：用于补充点击路径、批量场景和不确定问题。

## 核心判断

当前产品已经有一个成立的主方向：像歌词播放器一样复核字幕。

但它现在更像“单文件沉浸播放器”，还没有变成“多音视频转写工作台”。如果用户只处理一个短音频，链路基本顺；如果用户一次处理多个音视频，或者处理视频素材，用户会很快不知道当前任务、整体进度和下一步在哪里。

最佳方向：

- 首页是任务工作台，负责多文件、队列、进度、批量导出。
- 复核页是单文件工作区，负责听、看、改、标记、搜索、导出。
- 视频不另开一套流程，而是在音频复核基础上加视频预览和画面对照。

## 现有交互：单音频

### 当前路径

1. 用户打开应用。
2. 首页显示“字幕复盘工具”和“拖入音视频文件”。
3. 用户点击“导入文件”或拖入音频。
4. App 校验扩展名。
5. App 创建一个任务。
6. App 立刻生成 500 条 mock 字幕。
7. App 自动进入字幕复核页。
8. 用户点击底部播放按钮。
9. 用户点击某句字幕，播放器跳到该句时间。
10. 用户双击某句字幕，进入编辑框。
11. 用户按 Enter 或失焦，字幕自动保存。
12. 用户 hover 字幕右侧，点击复核状态或标签按钮：状态在 `待复核 / 保留 / 删除` 间切换，`重点` 和 `待确认` 可单独叠加。
13. 用户点击右上角“导出”。
14. 用户选择 SRT / TXT / JSON。
15. 浏览器下载文件。

### 点击成本

最短路径：

- 导入：1 次
- 播放：1 次
- 导出：2 次

真实复核路径：

- 每条字幕可能需要点击跳转、双击编辑、点击状态按钮。
- 500 条字幕会产生大量小目标点击。
- 状态按钮藏在 hover 后，实际操作会比表面点击数更费心。

### 当前不方便

- 导入后直接进入复核页，用户看不到任务创建和转写状态。
- 当前是 mock 字幕，真实转写的等待、失败、重试还没有交互。
- 早期模型里 `保留` 同时像结果状态，也像“已经看过”，二者不是一回事；已在状态模型整理中拆分。
- 早期模型里 `重点` 和 `待确认` 会替代“保留/删除”；已在状态模型整理中拆成独立标签。
- 编辑后没有撤销，也没有一键还原原文。
- 搜索缺失，长音频只能靠滚动和播放定位。
- 自动跟随播放头 3 秒后恢复，用户正在往回看时容易被拉走。

## 现有交互：单视频

### 当前路径

视频文件当前走和音频几乎一样的路径：

1. 用户导入 MP4/MOV。
2. 首页用视频图标显示。
3. App 进入同一个字幕复核页。
4. 底部播放器使用 `<video>` 元素。
5. 真机测试确认：视频元素存在，但 `display: none`，用户看不到画面。

### 当前不方便

- 当前视频本质被当成“带视频后缀的音频”处理。
- 如果用户只想提取字幕，这可以作为 MVP。
- 如果用户需要按画面校对字幕，这条链路不够。
- 用户不能对照人物、场景、口型、画面节奏来调整字幕。
- 视频用户的工作链路通常更长：导入、转写、看画面、校字幕、检查断句、导出到剪辑软件。

## 现有交互：多文件/批量

### 当前路径

当前代码支持一次选择多个文件，也支持多次导入。

真机测试结果：

1. 用户一次上传 `test-a.wav` 和 `test-b.wav`。
2. App 为两个文件都创建任务。
3. App 自动进入最后一个上传文件 `test-b.wav` 的复核页。
4. 用户点击左上返回。
5. 首页显示两个文件。
6. 用户点击 `test-a.wav`。
7. App 进入 `test-a.wav` 的复核页。

### 点击成本

当前切换文件：

- 返回首页：1 次
- 点击另一个文件：1 次

当前批量导入后的问题不是多点两下，而是用户心智断了：

- 用户导入多个文件后被直接送进最后一个文件。
- 用户没有立即看到“这批文件都添加成功了吗”。
- 用户不知道下一步应该复核哪个。
- 用户不知道是否还有文件在排队。

### 当前不方便

- 没有真正的批量转写队列。
- 没有批量导出。
- 没有“下一个待复核文件”。
- 没有复核页内文件切换器。
- 没有多文件整体进度。
- 刷新页面后任务和编辑会丢失。
- 删除任务没有确认或撤销。
- 从复核页拖入新文件时弹窗有“替换当前 / 新建任务”，但这更像特殊情况，不应该成为主要多文件入口。

## 进度模型：现在有什么，缺什么

### 现在已有

- 内存里的 jobs 列表。
- 内存里的每个任务字幕 `segmentsMap`。
- 当前正在编辑的字幕。
- 当前播放器时间。
- 当前字幕状态：`keep`、`delete`、`important`、`review`。

### 现在不完整

- 当前字幕编辑后，主要保存在字幕 store；返回首页时才同步到任务 store。
- 页面刷新后，所有任务和进度都丢失。
- 没有稳定的“保存中 / 已保存”提示。
- 没有记录每个文件上次播放到哪里。
- 没有记录用户上次看到哪一行。

### 现在完全缺少

- 真实转写进度。
- 失败原因。
- 重试入口。
- 批量导出进度。
- 每条字幕是否已复核。
- 项目级持久化。

## 推荐交互：音频完整工作流

### 单音频导入

推荐路径：

1. 用户打开首页。
2. 用户导入 1 个音频。
3. 首页出现任务卡片。
4. 如果需要转写，任务显示“转写中”。
5. 转写完成后状态变为“待复核”。
6. 如果只有 1 个文件，可以自动进入复核页，或显示明显按钮“开始复核”。
7. 用户进入复核页。
8. 顶部显示文件名、复核进度、保存状态、搜索、导出。
9. 中间显示字幕流。
10. 底部显示播放器。
11. 用户完成复核。
12. 用户导出当前文件。
13. 用户回到首页，任务状态变为“已完成”或“已导出”。

### 复核页应该显示

顶部：

- 返回任务列表。
- 当前文件名。
- 文件切换下拉。
- 上一个/下一个待复核文件。
- 复核进度，例如 `已复核 182 / 500`。
- 保存状态，例如 `已保存`。
- 搜索入口。
- 导出按钮。

字幕区：

- 当前句高亮。
- 状态按钮不要完全隐藏。
- 每行至少能看出是否待复核。
- 删除态要清楚，但不能让文字完全不可读。
- 已修改要能还原原文。

播放器：

- 播放/暂停。
- 前后跳转。
- 倍速。
- 音量。
- 当前时间 / 总时长。
- 未来可加波形，但不是第一优先级。

### 字幕状态建议

当前状态把多个概念混在一起。建议产品上拆成两层：

1. 输出结果：保留 / 删除。
2. 标签：重点 / 待确认。

这样用户可以表达：

- 这句保留。
- 这句删除。
- 这句保留且重点。
- 这句保留但待确认。

已落地的 MVP 做法：初始状态明确为“待复核”，用户操作后变成保留或删除；重点、待确认作为独立标签叠加。

## 推荐交互：视频完整工作流

视频应该基于音频工作流扩展，而不是另起一个产品。

### 视频路径

1. 用户导入视频。
2. 首页任务卡片显示视频类型。
3. 转写完成后进入复核页。
4. 复核页出现视频预览区。
5. 用户可以播放视频并同步看字幕。
6. 用户可以折叠视频预览，只保留音频式字幕复核。
7. 用户导出 SRT/TXT/JSON。
8. 如果面向剪辑软件，SRT 是主出口。

### 视频页布局

桌面端推荐：

- 左侧或上方：视频预览。
- 主区域：字幕流。
- 底部：播放器 / 时间线。

如果屏幕较窄：

- 视频预览在上。
- 字幕在下。
- 播放器固定底部。

### 视频额外需要的能力

优先级高：

- 看得到视频画面。
- 当前字幕可叠加预览。
- 视频预览可折叠。

优先级中：

- 精细时间线。
- 字幕断句调整。
- 字幕开始/结束时间微调。

优先级低：

- 多轨字幕。
- 复杂剪辑时间线。

## 推荐交互：多文件/批量

### 多文件导入

当前行为：导入多个文件后，自动进入最后一个文件。

推荐行为：

1. 用户一次导入多个文件。
2. App 停留在首页任务工作台。
3. 首页显示“已添加 N 个文件”。
4. 任务列表显示所有文件。
5. 如果转写开始，逐个显示等待中、转写中、完成、失败。
6. 顶部出现主按钮“开始复核第一个待复核文件”。

这样用户能先建立全局感。

### 文件切换

推荐提供三种入口：

- 首页点击任务。
- 复核页顶部文件名下拉。
- 复核页按钮：下一个待复核。

切换时应该自动保存当前文件，并显示：

- `已保存`
- 或 `正在保存...`
- 或 `保存失败，请重试`

### 批量导出

首页支持多选任务。

多选后出现批量操作栏：

- 批量导出 SRT。
- 批量导出 TXT。
- 批量导出工程 JSON。
- 批量删除。

批量导出建议打包 zip：

- `文件A.srt`
- `文件B.srt`
- `文件C.srt`

MVP 可以先不做 zip，但必须清楚告诉用户每个文件会分别下载，避免浏览器连续弹下载造成混乱。

### 批量编辑

不建议第一版做复杂批量编辑。

优先做：

- 批量导入。
- 批量转写。
- 批量导出。
- 批量删除带撤销。

不优先做：

- 跨文件批量修改字幕。
- 跨文件批量改状态。

## 推荐信息架构

```text
App
├─ 任务工作台 Home
│  ├─ 导入按钮 / 拖拽区
│  ├─ 任务列表
│  │  ├─ 文件名
│  │  ├─ 文件类型
│  │  ├─ 转写状态
│  │  ├─ 复核进度
│  │  ├─ 字幕统计
│  │  └─ 单文件操作：打开 / 导出 / 重试 / 删除
│  └─ 批量操作栏：批量导出 / 批量删除
│
├─ 单文件复核页 Review
│  ├─ 顶部：返回 / 文件切换 / 进度 / 搜索 / 导出
│  ├─ 视频预览区，仅视频文件显示，可折叠
│  ├─ 字幕流
│  └─ 底部播放器
│
└─ 弹窗
   ├─ 替换当前文件
   ├─ 删除确认或撤销 toast
   └─ 导出设置
```

## 第一阶段 UI 改造建议

第一阶段不要追求大重构。优先把用户路径捋顺。

### 1. 首页变成真正任务工作台

改动目标：

- 多文件导入后停留首页。
- 任务卡片显示状态和复核进度。
- 增加“开始复核”入口。
- 单文件导入可以继续自动进入复核页，但需要有任务创建反馈。

### 2. 复核页顶部补齐导航

改动目标：

- 返回任务列表更明确。
- 显示保存状态。
- 显示复核进度。
- 增加文件切换下拉或“下一个待复核”按钮。

### 3. 视频显示画面

改动目标：

- 如果是视频文件，不要隐藏视频。
- 显示可折叠预览。
- 保持音频用户的简洁布局。

### 4. 持久化进度

改动目标：

- 先用本地持久化保存 jobs、segments、当前播放位置。
- 刷新后能恢复。
- 删除任务要能撤销。

## 已落地的交互整理

### 任务工作台

- 多文件导入后停留在首页任务工作台。
- 首页显示批量导入反馈，例如“已添加 2 个文件”。
- 用户可以从首页点击“复核第一个”进入队列第一项。
- 单文件导入仍保持快速进入复核页。

### 复核页多文件导航

- 复核页顶部显示当前文件名、复核进度和保存状态。
- 文件名可以展开任务列表，在复核页内切换文件。
- 多文件时提供“下一个”入口，优先跳到仍有待复核字幕的文件。

### 状态模型

- `status` 现在只表示复核决策：`review`、`keep`、`delete`。
- `important` 独立表示重点标签。
- `needsCheck` 独立表示待确认标签。
- 新导入的 mock 字幕默认都是 `review`，用户操作后才进入已复核进度。
- 导出 SRT/TXT 仍按 `status === 'delete'` 过滤删除字幕。

## 需要产品确认的问题

这些问题会影响 UX 设计，不能硬猜：

1. 主要用户场景是什么？
   - 短视频字幕？
   - 会议录音整理？
   - 访谈稿？
   - 课程/播客？
   - 投放/素材复盘？

2. 视频用户是否必须看画面？
   - 如果必须看，视频预览是一等入口。
   - 如果只是从视频里提取音频，视频预览可以折叠或次要。

3. 多文件导入后是否应该自动开始转写？
   - 自动开始适合效率工具。
   - 手动开始适合需要控制成本或选择模型的工具。

4. 复核完成的定义是什么？
   - 每条都看过？
   - 没有 `待复核` 和 `待确认`？
   - 已经导出？
   - 用户手动点击“完成复核”？

5. `重点` 的后续用途是什么？
   - 只是用户自己标记？
   - 导出到 TXT 摘要？
   - 给剪辑软件做 marker？

6. 是否需要说话人区分？
   - 会议和访谈强需要。
   - 短视频字幕可能不需要。

7. 是否需要云端同步或团队协作？
   - 如果不需要，第一版本地持久化足够。
   - 如果需要，保存、冲突和权限会影响整个 UX。

## 当前结论

当前 UI 的核心美感方向可以保留：沉浸、安静、像歌词一样跟随播放。

但交互骨架需要改成：

```text
多文件由首页管理
单文件由复核页处理
视频在单文件复核页加画面
进度必须持久保存
批量只做导入、转写、导出，不急着做批量编辑
```

这能同时覆盖三个场景：

- 单音频：最快进入复核。
- 单视频：在音频复核基础上加画面对照。
- 多文件：先看队列，再逐个复核，最后批量导出。
